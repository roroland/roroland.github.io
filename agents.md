## Agents Documentation

This project is a personal site built with [Eleventy](https://www.11ty.dev/) (11ty), using Sass for CSS preprocessing and PostCSS for post-processing. Below are the key components and build processes involved:

### Build Tools & Scripts

| Script         | Command                | Description                                              |
| -------------- | ---------------------- | -------------------------------------------------------- |
| `devserver`    | `npm run devserver`    | Eleventy dev server (`eleventy --serve`)                 |
| `watch:sass`   | `npm run watch:sass`   | Watches SCSS files and compiles to CSS                   |
| `start`        | `npm start`            | Runs devserver + watch:sass in parallel                  |
| `build:site`   | `npm run build:site`   | Generates static site via Eleventy                       |
| `build`        | `npm run build`        | Full pipeline: Sass → Concat → PostCSS → Compress → Site |
| `compile:sass` | `npm run compile:sass` | Compiles `scss/style.scss` → `css/style.comp.css`        |
| `concat:css`   | `npm run concat:css`   | Concatenates CSS files into `style.concat.css`           |
| `prefix:css`   | `npm run prefix:css`   | Autoprefixes CSS via PostCSS → `style.prefix.css`        |
| `compress:css` | `npm run compress:css` | Compresses CSS → `style.css`                             |
| `lint:css`     | `npm run lint:css`     | Lints `scss/**/*.scss` with Stylelint                    |
| `lint:css:fix` | `npm run lint:css:fix` | Same as above, auto-fixing what is safe to fix           |

### CSS Build Pipeline

```
scss/style.scss
  → (Sass)
css/style.comp.css
  → (concat)
css/style.concat.css
  → (PostCSS + Autoprefixer)
css/style.prefix.css
  → (Sass compress)
css/style.css  (final output)
```

### SCSS Architecture

`scss/style.scss` solo declara el orden de las capas; no contiene reglas.

```
scss/
├── style.scss            # @use de las capas, en orden de cascada
├── abstracts/            # Sin salida CSS (salvo :root)
│   ├── _functions.scss   # rel()
│   ├── _tokens.scss      # :root: colores, espaciados, offsets
│   ├── _breakpoints.scss # $breakpoints + mixins up()/down()/down-landscape()
│   └── _extends.scss     # placeholders %h3/%h4/%h5
├── base/                 # _reset, _root (html/body), _typography
├── layout/               # _container, _helpers (.line, .offset, .menuTop)
├── animations/           # keyframes genéricos
├── components/
│   ├── intro/            # _intro, _heroText
│   ├── about/            # _about, _aboutSummary, _introAbout, _moreAbout, _world, _timeline
│   ├── skills/           # _skills, _avatar, _skillsNav
│   ├── work/             # _work, _workGallery, _sizes
│   ├── feature/          # _feature, _featureVariants, _featureContent, _placeholder
│   ├── blog/             # _blog, _postList, _post (listado y artículo)
│   ├── _mainNav.scss
│   ├── _gotoTop.scss
│   └── _footer.scss
├── utilities/            # _animatable (.animatable + fadeInUp)
└── decorations/          # _swirl (capas SVG animadas)
```

Reglas del contrato (aplicadas por Stylelint):

- `abstracts/` no emite selectores; solo `:root`, variables, funciones y mixins.
- Un fichero = un componente = un selector raíz. Anidamiento máximo 3.
- `@keyframes` a nivel raíz del fichero, con prefijo del componente.
- Nada de `@extend` a clases reales: usar placeholders de `abstracts/_extends.scss`.
- Las media queries se escriben con mixins por dispositivo: `@include tablet`,
  `@include laptop`, `@include desktop`, `@include desktop-hd`, `@include desktop-ultra`
  y `@include phone-large` (ancho mínimo), o `@include phone` / `@include phone-landscape`
  (solo teléfono). Ver `abstracts/_breakpoints.scss`.
- `style.scss` no contiene reglas.

### Blog (`/blog/`)

- `blog/index.njk` genera la home del blog en `/blog/` y recorre
  `collections.posts | reverse` (más recientes primero).
- `blog/posts/posts.json` es un data file de carpeta: asigna el layout de post,
  la tag `posts` y el permalink `/blog/{{ page.fileSlug }}/` a cada `.md`.
- Añadir un post = crear un `.md` en `blog/posts/` con front matter
  `title`, `description`, `date` y `tags`. No hay que tocar la config.
- `eleventy.config.js` expone los filtros `readableDate` y `htmlDateString`,
  formateados en UTC para evitar saltos de día por zona horaria.
- Layouts: `layouts/base.njk` (head/nav/footer) → `layouts/blog.njk` (listado)
  y `layouts/post.njk` (artículo + prosa). La nav vive en
  `_includes/partials/mainNav.njk` y la usan tanto la home como el blog.

### Customization

Para nuevas secciones, crear un fichero en `scss/components/<bloque>/`, añadirlo a
`scss/components/<bloque>/_index.scss` y `@forward` del bloque en
`scss/components/_index.scss` respetando el orden de cascada.
